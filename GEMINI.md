## Coding Conventions
- Keep code clean and readable.
- Use meaningful variable and function names.
- Prefer simple solutions over unnecessary complexity.
- Follow accessibility best practices.
- Keep changes focused and explain important changes.
- Do not introduce unnecessary dependencies.
- Ask before making major architectural changes.

## Git Conventions
Use Conventional Commits, such as:
- feat: add a feature
- fix: fix a bug
- docs: update documentation
- chore: update project configuration

## AI Assistant Rules

- Explain what you changed.

## Development Workflow

- Test changes before committing them.
- Keep each commit focused on one logical change.
- Review the Git diff before creating a commit.
## FE-04 Project Rules

* **Form validation:** All required form fields must be validated before submission, including empty, whitespace-only, invalid-format, and relevant boundary inputs.

* **Accessibility:** Every form control must have a clear associated label, keyboard navigation must work, and validation errors must not rely only on color.

* **Testing:** Validation logic must have automated tests covering valid inputs, invalid inputs, required fields, and important edge cases. Tests must be run before committing changes.

* **Verification:** Do not claim a feature is complete until the relevant tests have actually been executed and the Git diff has been reviewed.

* **Dependencies:** Use the existing HTML, CSS, and JavaScript setup and avoid adding dependencies unless they are necessary for the requested feature.
